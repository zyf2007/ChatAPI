## P2：#48 的失败恢复跨会话写入

位置：PR 的 `frontend/src/hooks/useChatWorkspace.ts:488–494`（`handleDraft` catch）。
该分支无条件把捕获的 `rawChunk` 拼回当前 React 输入状态，没有校验发送时的
`conversation_id` / `request_id` 是否仍是当前编辑对象。

复现流程：

1. 打开等待中的会话 A，输入 `private text for first conversation`，按 Enter。
2. 暂缓该 WebSocket 命令确认，切换到另一个等待中的会话 B；B 输入框为空。
3. 对 A 的命令返回 `workspace.command_error`。
4. B 输入框变成 A 的原始文本；用户后续可能把它误发给 B 的请求方。

桌面和移动 Chromium 均在最后一个空输入断言稳定失败，实际值都是 A 的原文。
确定性的 WebSocket harness 位于 `fixtures/workspaceHarness.ts`，完整脚本为
`pr48-regression.spec.ts`。它显式标注 `test.fail`，因此运行器显示的“2 passed”
表示 **两个已知失败均复现**，不表示 PR 已修好。

复测（需要先启动 PR #48 快照前端）：

```bash
CHATAPI_TEST_PR48=1 CHATAPI_TEST_WEB_BASE_URL=http://127.0.0.1:5194 npm --prefix frontend run test:e2e -- pr48-regression.spec.ts --workers=1
```

修复应把待发送片段和恢复动作绑定到发送时的会话/请求身份，避免恢复到新编辑对象；
修复后移除 `test.fail` 并运行相同流程。

这些 PR 的验证分别进行，未验证它们全部合并后的组合状态。特别是 #49、#51、#52
都会修改 `package.json` 的测试列表，合并时需要保留所有测试文件。
